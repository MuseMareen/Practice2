# Практическая работа №2

## Дисклеймер

Данное веб-приложение и скрипты эксплуатации разработаны исключительно в учебных и исследовательских целях в рамках выполнения лабораторной работы по курсу информационной безопасности.
Все уязвимости (Stored XSS, SQL Injection) внедрены в приложение намеренно для изучения механизмов их возникновения, способов эксплуатации и методов защиты. Приложение предназначено для запуска только в изолированной локальной среде.

### Описание проекта

Веб-приложение салона красоты **«Beauty Studio»** на базе **Python (Flask)** и **SQLite**, содержащее намеренно реализованные уязвимости из списка **OWASP Top 10**, скрипт автоматизированной эксплуатации и патч безопасности в формате `diff`.

## Часть 1. Для установки и запуска веб-приложения:

1. Клонируйте репозиторий и перейдите в директорию проекта:
   ```bash
   git clone <URL_вашего_репозитория>
   cd Web_app
   ```

2. Создайте и активируйте виртуальное окружение:
   ```bash
   # для Windows
   python -m venv venv
   venv\Scripts\activate

   # для Linux / macOS
   python3 -m venv venv
   source venv/bin/activate
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Запустите веб-приложение:
   ```bash
   python app.py
   ```
   Приложение запустится локально по адресу: `http://127.0.0.1:5000` (база данных `beauty_studio.db` создастся автоматически при первом запуске).

### Реализованные уязвимости

1. **Stored XSS (Cross-Site Scripting — OWASP A03:2021 Injection)**
   * **Где находится:** `templates/admin.html` (`{{ row[1] | safe }}`).
   * **Причина:** Использование фильтра `| safe` отключает встроенное HTML-экранирование шаблонизатора Jinja2. Любой JavaScript-код, переданный в поле «Имя» при отправке формы `/book`, сохраняется в БД и выполняется в браузере при открытии страницы `/admin`.

2. **SQL Injection (OWASP A03:2021 Injection)**
   * **Где находится:** `database.py`, функция `search_by_phone(phone)`.
   * **Причина:** Прямая конкатенация пользовательского параметра `phone` в SQL-запрос через f-строку (`f"SELECT * FROM appointments WHERE phone = '{phone}'"`). Позволяет обойти условие фильтрации (`' OR '1'='1`) или выполнить `UNION`-инъекцию для извлечения произвольных данных.

## Часть 2. Эксплуатация уязвимостей

Для демонстрации эксплуатации уязвимостей разработан скрипт `exp.py`.

1. Убедитесь, что веб-приложение запущено (`python app.py`).
2. В новом окне терминала выполните:
   ```bash
   python exp.py
   ```

### Что делает скрипт:
* Отправляет `POST /book` с XSS-нагрузкой (`<script>...</script><img src=x onerror=...>`) и проверяет её наличие в неэкранированном виде на странице `GET /admin`.
* Отправляет `GET /search` с полезной нагрузкой `' OR '1'='1` для обхода фильтра и получения списка всех телефонов клиентов.
* Отправляет `GET /search` с нагрузкой `' UNION SELECT 1,'injected','data','--','--','pwned' --` для демонстрации внедрения произвольных строк в вывод.

## Часть 3. Устранение уязвимостей (Патчинг)

Исправление обеих уязвимостей оформлено в виде патча `security_fix.patch`:
* в `database.py` небезопасная f-строка заменена на параметризованный SQL-запрос с плейсхолдером `?`;
* в `templates/admin.html` удалён фильтр `| safe`, возвращающий стандартное экранирование HTML в Jinja2.

### Применение патча
1. Проверьте корректность патча без внесения изменений:
   ```
   git apply --check security_fix.patch
   ```
2. Примените патч:
   ```
   git apply security_fix.patch
   ```
3. Перезапустите приложение (`python app.py`) и повторно запустите `python exp.py` — обе атаки будут заблокированы.
